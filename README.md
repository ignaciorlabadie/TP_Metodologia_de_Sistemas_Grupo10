## Forma de trabajo

Cada integrante trabajó en su propia rama y los cambios se integraron a `dev` mediante pull requests. Se usaron commits convencionales (`feat:`, `fix:`, `docs:`, `refactor:`, `revert:`) y se produjeron revisiones dentro de GitHub. Durante el desarrollo se generó un conflicto real que quedó documentado en la carpeta `conflictos/`.
